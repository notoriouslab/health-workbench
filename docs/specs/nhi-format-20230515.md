## 已確認的程式錯誤

- **XML 範圍**：X2 第 1 頁明列 r1～r14，第 10～17 頁定義 r9～r14。
  過去以部分匯出檔推論「XML 無 r9～r14」不成立；缺少節區僅代表該來源未提供。
- **成人健檢**：J2 第 13 頁、X2 第 12 頁，r10.14 是總膽固醇 TC，
  r10.15 是三酸甘油酯 TG。舊欄位表兩者對調，現已修正。
  J2 第 14～15 頁、X2 第 13～15 頁也確認腎功能、肝功能及 B/C 肝欄位：
  r10.35/.36 是 B 肝表面抗原、.37/.38 是 B 肝檢查結果；
  .39/.40 是 C 肝抗體、.41/.42 是 C 肝檢查結果，並非「追蹤」欄位。
- **住院**：J2 第 4～7 頁、X2 第 4～7 頁定義 r2.1～.91 及 r2_1.1～.6。
  現在投影為 `encounters.type=inpatient`，日期取入院日期，醫囑以 .4/.5/.6
  對應代碼／名稱／總量。住院醫囑沒有給藥日數欄，`days_supply` 保持 null；
  執行期間、出院日及全部診斷／處置碼保留在父事件 `canonical`。
- **中醫**：補齊 r9.23～.26 及 r9_1 欄位表；接受 J2 表格中大寫的 `R9_1.*`。
- **過敏**：J2 第 8～9 頁、X2 第 8 頁新增／定義 r4.9～.12；r4.3 上傳醫師
  自修訂日起停止提供。缺少或 null 不視為格式錯誤，也不從其他資料推測醫師。

## 官方文件自身的差異與處理原則

| 議題 | 證據 | 實作決策 |

| 申請日期代碼 | J2 第 3 頁表格為 b2.1，第 18 頁範例為 b1.2；X2 第 2 頁為 b1.2 | 兩者均識別並原樣保存；同時存在不擅自覆蓋或選定優先值 |
| 日期長度 | J2 第 4、7 頁部分 X(8) 日期註記為 YYYYMM；X2 第 4、7 頁及 J2 第 20 頁範例為 YYYYMMDD | 延續接受 6／8 碼日期；月精度保持 YYYY-MM，不補造某日 |
| 數字與字串 | J2 表格數值欄在範例中混用 JSON 數字與數值字串 | 保留既有數值轉換與原值 canonical；代碼不轉數字、不移除前導零 |

## 儲存與相容性

Python JSON、App JSON/XML adapter 版本升為 **1.1.0**，SQLite schema 維持 **6**。

- r1/r2/r3/r6/r7/r8/r9/r10/r11 投影至既有資料表，原紀錄（含未知欄位、巢狀明細）
  依既有 canonical 規則保存：空白折疊、null／空字串等價、巢狀清單排序。
  canonical 並非逐位元的來源備份；自由文字報告另由 report_text 保留。
  已知但未投影的欄位仍可由來源追溯取得；不能聲稱所有欄位皆有 UI。
- r4/r5/r12/r13/r14 仍以 `UNPARSED_HAS_DATA` 表示尚無專用臨床投影。
  此次修正以前僅計數而未保存的問題：完整內容（含所有巢狀值）寫入
  `source_documents.import_stats.nhi_retained[section]`。未來節區、基本資料與 r0 聲明
  也存於此處。這是既有 JSON 欄位的附加鍵，原統計鍵與表結構不變。
- 逐筆失敗內容存於 `import_stats.nhi_failed_records[section][source_index]`，
  品質報告保留 `parse_errors`；有效同節區紀錄仍會繼續處理。
  現有儀表板／EPUB 不會展示這些節區，但來源 metadata 可能隨匯出載入，
  匯出檔與資料庫一樣含健康資料，不能把「未顯示」視為已去除資料。
- 原紀錄指紋、檔案 SHA-256 去重、歸戶護欄與原始控制字元容忍皆維持。
  新建空庫也必須有 b1.1，否則不建立 profile 或來源紀錄。
- **既有資料不自動重寫**：舊的 r10 `extra_json` 顯示名稱及舊版丟失的未投影資料
  不會因更新程式而恢復；同 SHA 檔案仍跳過。需要修正歷史內容時，先備份，
  使用保留的來源檔建立新的資料庫再核對；不要直接更名錯置的舊數值或刪除來源。
  跨匯出檔若代碼大小寫不同，仍可能有不同紀錄指紋，這是保留原指紋契約的取捨。
- XML 支援仍在 App；本次未新增 Python CLI XML adapter。

## 回歸證據

新增 `tests/fixtures/nhi_official_20230515.json` 完全由測試程式作者構造，
使用「合成」文字、SYN 代碼及既有測試遮罩 ID，未擷取任何患者檔案或 PDF 個案。
測試涵蓋全部 14 節區、r2 醫囑錯位防護、TC/TG 分辨、大寫醫囑、兩種肝炎欄位形狀、
未知節區保存、null／缺少／無資料／單筆物件、壞紀錄續行及重複匯入。
XML 由同一合成結構序列化，另外比對 Python/JS 完整資料庫及品質報告。

執行方式（Python 需 pytest 與 PyYAML；Node 需支援 node:sqlite）：

```sh
python -m pytest tests/test_nhi.py tests/test_nhi_official.py
node --test app/tests/adapters/nhi_official.test.mjs app/tests/adapters/nhi_xml.test.mjs app/tests/adapters/nhi_adapter.test.mjs app/tests/parity/parity.test.mjs
```

非 `python3` 環境可用 `PYTHON` 指定 Python 執行檔。NHI 測試路徑使用
`fileURLToPath`，可處理 Windows 與含中文的資料夾名稱。
