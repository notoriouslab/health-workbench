# app-import-gui Specification

## Purpose

匯入流程的使用者介面層：選檔與拖放、進度與結果報告、匯入歸屬選擇、
防護情境（重複檔、歸戶不符、壞檔）的呈現，以及匯入紀錄卡的批次摺疊與
批次救援入口。與 app-import-engine 的引擎行為分層，介面只負責呈現與
確認（change tauri-desktop-app，2026-08-10）。

## Requirements

### Requirement: 選檔與拖放匯入

使用者 MUST 能以系統選檔對話框或拖放檔案至視窗啟動匯入；格式由引擎
自動判型，使用者 MUST NOT 需要指定檔案類型。無法識別的檔案 MUST
顯示支援格式清單（自 adapter 註冊表產生）。

**拖入資料夾時的判型順序 MUST 為：先問集合判型，沒有結果才回退既有的
單一檔案解析。** 集合判型的條件嚴格（要求特定檔案存在且通過內容判型），
既有的資料夾解析條件寬鬆（有任何符合副檔名的檔案就算，且會下潛一層）。
寬鬆的放在後面，含有無關檔案的來源才不會被誤判成另一種格式。

無法識別的**資料夾** MUST 比照無法識別的檔案，顯示完整支援格式清單，
MUST NOT 只提示單一格式（支援的來源已不只一種）。

資料夾列舉 MUST 有項目數上限：使用者可能選到大型目錄（如下載資料夾），
無上限列舉會使介面停止回應。達到上限時以已收集到的項目進行判型。

**判型面板顯示時 MUST 保有可容納約五行內容的最小高度**，MUST NOT 被
分頁內其他區塊壓縮到只剩一行（2026-08-19 走查回饋：面板被上下區域擠扁，
成員選擇與開始匯入難以操作）。面板未顯示時不佔空間的既有行為不變。

#### Scenario: 拖放匯入
- **WHEN** 使用者將健保 JSON 檔拖入視窗
- **THEN** 顯示判型結果（健保存摺醫療類 JSON）與確認鈕，確認後開始匯入

#### Scenario: 不支援的檔案
- **WHEN** 使用者拖入一張照片
- **THEN** 顯示「無法識別」與目前支援格式清單，不進入匯入流程

#### Scenario: 拖入多檔來源的資料夾
- **WHEN** 使用者拖入含特定摘要檔與逐次紀錄目錄的記錄卡資料夾
- **THEN** 由集合判型識別，確認面板顯示資料夾名稱、檔案數與合計大小

#### Scenario: 既有資料夾情境不受影響
- **WHEN** 使用者拖入既有來源的匯出資料夾
- **THEN** 集合判型無結果，回退既有解析路徑，行為與擴充前相同

#### Scenario: 無法識別的資料夾
- **WHEN** 使用者拖入一個兩種路徑都不認得的資料夾
- **THEN** 顯示完整支援格式清單，不進入匯入流程

#### Scenario: 面板不被壓扁
- **WHEN** 匯入分頁同時存在匯入紀錄卡等高度內容且判型面板顯示中
- **THEN** 面板高度足以同時看見判型結果、成員選擇器與「開始匯入」鈕
  （約五行內容），內容更多時面板內部捲動

### Requirement: 進度與結果報告

匯入中 MUST 顯示進度（進度文字與百分比規則見下）；完成後 MUST 顯示增量
結果報告卡：各節區筆數、新增/重複（冪等跳過）統計、品質旗標摘要、
未對照項提示，結構沿用既有增量品質報告。

百分比 MUST 僅於 totalBytes > 0 時顯示，否則只顯示已處理筆數（寧可
不顯示也不顯示假的百分比）。zip 匯入的容器快篩期間 MUST 顯示「正在檢查
檔案是否曾經匯入…」且不帶百分比（該階段為秒級）。百分比 MUST NOT 提前
到達 100%：到達 100% 時匯入隨即完成。

**多檔來源的報告卡** MUST 額外顯示批次名稱、檔案總數與其中新檔數，
並以收合區塊提供逐檔明細（檔名、狀態、筆數）。逐檔明細 MUST 收合，
上百個檔案不應淹沒節區摘要。單檔匯入的報告卡呈現 MUST NOT 改變。

整批檔案都命中既有內容時 MUST 明確告知「這批檔案先前都已匯入」；
部分命中時 MUST 顯示新檔數，MUST NOT 只呈現總數讓使用者誤以為全部
重新處理了一次。

#### Scenario: 匯入完成報告
- **WHEN** 匯入一份含新資料與重複資料的健保 JSON
- **THEN** 報告卡顯示各節區新增與跳過筆數，與 CLI 版增量報告數字一致

#### Scenario: 匯入中防重入
- **WHEN** 匯入進行中
- **THEN** 再次拖入檔案被拒並提示等待，檢視頁資料維持匯入前狀態直到
  完成（單交易）

#### Scenario: 批次報告卡
- **WHEN** 完成一次多檔來源匯入
- **THEN** 標題顯示批次名稱、檔案總數與新檔數；逐檔明細以收合區塊呈現

#### Scenario: 整批重複
- **WHEN** 將同一批檔案再次匯入
- **THEN** 顯示「這批檔案先前都已匯入」，資料庫零新增

#### Scenario: 百分比 fallback
- **WHEN** adapter 回報 totalBytes 為 0
- **THEN** 進度文字僅含已處理筆數，不含百分比

#### Scenario: 進度不再停在假 100%
- **WHEN** 匯入 zip 來源
- **THEN** 顯示的百分比隨解壓進度前進，到達 100% 時流程即結束

### Requirement: 防護情境的使用者呈現

重複檔案（SHA-256 相同）MUST 顯示原歸屬成員名稱與原匯入時間並
跳過；歸戶防護（所選成員已綁定的遮罩身分證與檔案 b1.1 不符）
MUST 顯示成員名稱與雙方遮罩值並零寫入；部分失敗續行（對齊
health-database schema v3 契約）MUST 呈現「成功節區/失敗節區」
明細，失敗明細可展開。

#### Scenario: 重複檔案（含歸屬）
- **WHEN** 拖入一份先前已由成員「本人」匯入的檔案（不論本次歸屬
  選誰）
- **THEN** 顯示原歸屬成員「本人」與原匯入時間並跳過，資料庫零寫入

#### Scenario: 歸戶不符（引擎第二層護欄）
- **WHEN** b1.1 預讀不可得（header 64KB peek 的已知限制）使面板
  未能預判不符，使用者對已綁定不同身分證的成員按下開始匯入
- **THEN** 引擎護欄中止，報告區顯示成員名稱與兩個遮罩值，
  資料庫零寫入

#### Scenario: 部分失敗續行
- **WHEN** 某節區含 5 筆無法解析的紀錄，其餘節區正常
- **THEN** 正常節區完成匯入，報告卡標示失敗節區與筆數，展開可見
  逐筆錯誤摘要

### Requirement: 匯入歸屬選擇

判型確認面板 MUST 整合成員選擇器：列出全部成員（顯示名稱＋已綁定
遮罩身分證），**無預設值、必選**（未選擇時「開始匯入」停用），並
提供「＋新增成員」就地建立；所選成員名稱 MUST 顯著呈現。健保檔
MUST 於選定成員當下顯示身分證比對三態提示（將綁定／相符／不符），
不符時「開始匯入」MUST 停用。零成員資料庫首次匯入 MUST 於面板
就地新增第一位成員。匯入完成報告卡 MUST 顯示歸屬成員名稱。

#### Scenario: 必選無預設
- **WHEN** 拖入健保 JSON，判型確認面板出現
- **THEN** 成員選擇器無預選值且「開始匯入」停用，選定成員後才可
  開始

#### Scenario: 不符即時停用
- **WHEN** 面板中選到與檔案 b1.1 不符的已綁定成員
- **THEN** 即時顯示兩個遮罩值與不符說明，「開始匯入」停用；改選
  相符成員後恢復可按

#### Scenario: 就地新增成員
- **WHEN** 匯入媽媽的健保檔但成員清單只有「本人」
- **THEN** 於選擇器點「＋新增成員」輸入「媽媽」即建立並自動選定，
  不需離開匯入流程

### Requirement: 匯入紀錄卡的批次摺疊與批次救援

App 的匯入紀錄卡 MUST 將同一批來源檔案（同 adapter ＋同匯入時刻）摺疊為
一列，顯示檔案數與該批各表合計，並可展開檢視逐檔。一次多檔匯入會產生
數十筆來源紀錄，逐列呈現使該區塊無法閱讀。

批次列 MUST 提供對**整批**生效的刪除與改歸屬；逐檔操作 MUST 保留在展開
後的每一檔上：刪除單一逐日檔仍有正當用途（某檔解析錯誤要單獨移除重匯），
而只能逐檔操作等於沒有解決可讀性問題。

批次操作 MUST 在單一交易內完成，全成功或全回復。執行前 MUST 顯示整批的
影響範圍（檔案數與各表筆數合計）並要求確認。

缺少匯入統計的批次 MUST 明示為「無統計」，MUST NOT 顯示為新增 0 筆：
兩者在畫面上是不同的事實。

批次的組成 MUST 由檢視層計算後傳入引擎層，引擎層 MUST NOT 自行推導批次：
分組規則屬於呈現層的決定，引擎不該知道。

#### Scenario: 多檔匯入後的紀錄呈現
- **WHEN** 拖入一整張 CPAP 記錄卡後檢視匯入紀錄卡
- **THEN** 該批顯示為一列「N 個檔案」與該批各表合計，展開後可見逐檔檔名
  與各檔自己的操作入口

#### Scenario: 剔除整批
- **WHEN** 於批次列選擇剔除整批並確認
- **THEN** 確認面板先列出檔案數與各表筆數；確認後該批全部來源紀錄與其
  資料列於單一交易內清除，其他批次與其他成員的資料不變

#### Scenario: 批次操作中途失敗
- **WHEN** 批次刪除或改歸屬在中途失敗
- **THEN** 全庫回復至操作前狀態（無半刪半搬），並顯示失敗訊息

#### Scenario: 單檔批次
- **WHEN** 某批只有一個檔案（健保與 Apple 皆為單檔匯入）
- **THEN** 該列直接顯示檔名與單檔操作，不出現「1 個檔案」的摺疊層
